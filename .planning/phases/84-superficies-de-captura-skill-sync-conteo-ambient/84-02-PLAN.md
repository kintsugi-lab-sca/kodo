**A. `.claude/skills/kodo-capture/SKILL.md` — fichero nuevo.**

Frontmatter YAML con cuatro claves, en este orden: `name: kodo-capture`; `description` en español,
una frase de qué + una de cuándo, que diga (a) que captura al inbox global de kodo, (b) cuándo
usarla —el operador suelta una idea o un pendiente ajeno a la tarea en curso y no quiere perder el
hilo—, y (c) que shellea `kodo capture` y nunca escribe el fichero; `argument-hint: "<texto de la idea>"`;
`allowed-tools: Bash(kodo capture *)`. La `description` se mantiene por debajo del tope de 1 536
caracteres del listado de skills. El patrón de `allowed-tools` es deliberadamente **estrecho** — un
comodín amplio pre-aprobaría tools arbitrarias en el turno de invocación.

Cuerpo en español, por debajo de 500 líneas y muy corto en la práctica (esta skill hace una sola
cosa). Debe contener, y solo esto:

1. Un H1 y una frase de propósito.
2. **La invocación canónica**, precedida en la línea inmediatamente anterior por el marcador HTML
   estable `<!-- kodo:capture:invocacion -->` y encerrada en un **único** bloque cercado con lenguaje
   `bash`. El contenido del bloque es **exactamente una línea**, el literal LOCKED de D-11:
   `kodo capture --origin skill -- "<texto>"`. El placeholder es `<texto>`, no una variable de
   sustitución: el modelo sustituye y escapa (arbitraje declarado en `must_haves.flagged_assumptions`).
3. Una sección de reglas numeradas en negrita, siguiendo la forma de `worktree-cleanup`:
   - El texto va como **un solo** argumento; si contiene comillas, se escapan al llamar a la tool.
   - Los flags van **siempre antes** del separador `--`; si fueran después, el parser los leería como
     parte del texto.
   - El texto se pasa **verbatim**: no se reescribe, no se resume, no se traduce, no se corrige la
     ortografía y no se le añade contexto de la sesión que el operador no haya tecleado.
   - No se deriva ni se inventa el proyecto: el comando hereda el directorio de trabajo de la sesión
     y kodo calcula el tag por su cuenta (D-12).
   - Si no hay texto, se pregunta al operador; **no** se ejecuta el comando con el argumento vacío.
   - Si el comando termina con código distinto de 0, se reporta su stderr verbatim y se para. Nunca
     se reintenta escribiendo el fichero del inbox a mano: kodo tiene un único writer y ese writer es
     el comando.
   - Esta skill **solo** captura: para listar, enrutar o descartar está `kodo inbox` (D-15).

**Restricción estructural que el test va a comprobar:** en todo el fichero debe haber **un solo**
bloque cercado y **una sola** línea de comando de shell. Cualquier ejemplo adicional, alternativa
comentada o «variante para el caso X» rompe el invariante de writer único.
